# Identity & Marks

A logo is not "a small graphic". It is the most compressed, most reused, most adversarially scaled piece of design you will make. It must work at 16px, at 100m, in one color, embroidered, photocopied, and reversed out of a photo. This file covers mark construction and the brand system around it.

---

## 1. Mark types — what each is good at

| Type | Description | Strengths | Weaknesses |
|---|---|---|---|
| **Wordmark** | the name, typographically designed | immediate name recognition; typography becomes identity | weak at tiny sizes; needs the name to be short |
| **Lettermark / monogram** | initials, designed | compact; works as app icon, social avatar | says nothing about the business on its own |
| **Pictorial mark** | recognizable object, stylized | memorable, scalable, wordless | literal; can limit the brand as it grows |
| **Abstract mark** | geometry with meaning (Nike swoosh) | unlimited interpretation; ownable | requires marketing to acquire meaning |
| **Emblem / badge** | name inside a container | heritage, authority, craft | dies at small sizes; hard to place on clutter |
| **Combination mark** | symbol + name, separable | flexible: use together or apart | two elements to keep in proportion |
| **Responsive/family mark** | mark that changes by context | modern, systematic | needs a real system to keep coherent |

**Choose by growth stage and context:** a new startup wants a combination mark (flexibility); a food brand can carry an emblem (craft); a digital product needs a lettermark/abstract that survives as a 24px icon.

## 2. Construction — build it on a grid

Marks built from a construction system look *inevitable* rather than decorated. This is the Bauhaus/Swiss heritage applied to identity.

1. **Set the unit.** Choose a base module (a circle radius, a square side, a stroke width) and express every dimension as a multiple of it. (Classic examples: the Apple mark's overlapping-circle construction; the IBM mark's stripe grid.)
2. **Draw the construction field first:** a square artboard with a grid (e.g. 8×8 or 12×12 modules), plus construction circles/axes where curves occur.
3. **Build from primitives:** circles, squares, triangles, and lines at consistent weights. Curves should be *one* radius family (or a stated progression), not freehand.
4. **Optical corrections** (math is wrong here):
   - Round shapes overshoot square neighbors by 1–2% (a circle beside a square must look the same height).
   - Pointed forms (A, V, W, star) overshoot at the point and tuck at the sides.
   - Reduce stroke weight where strokes converge (intersections look heavier); lighten horizontals slightly in a letterform (the "horizontal is lighter" rule).
   - Balance enclosed counters so they read as equal (P/B/R bowls).
5. **Positive/negative:** design the counter-forms (the holes) as carefully as the shapes. A mark whose negative space is careless collapses in one color.
6. **Simplify until it hurts**, then remove one more element. The mark must be describable in one sentence ("a circle cut by a diagonal bar") — if the description needs three clauses, it isn't a mark yet.

## 3. Lockups & rules

- **Lockups:** horizontal (symbol left, name right), stacked (symbol above name), and standalone symbol. Define all three *once*, with the baseline alignment explicit (usually cap-height of the name aligns to a symbol feature).
- **Clear space:** at minimum, a margin equal to the mark's x-height (or the symbol's cap-height) on all sides. Never let type, image edges, or other logos enter it.
- **Minimum size:** define in both mm (print) and px (screen). Typical: a wordmark dies below ~25mm / 100px wide; a symbol can go to 16px if simplified.
- **Color versions required:** full-color on light, full-color on dark, one-color black, one-color white (knockout). If any of these fail, the mark is not finished — often the fix is thickening strokes or closing counters.
- **Never:** stretch, rotate, add drop shadows/glow, recolor outside the palette, place on busy imagery without a scrim, or re-typeset the name in a different face.

## 4. Type in identity

- The wordmark's face is a brand asset: specify the family, weight, and any customizations (modified R, tightened spacing, cut terminals).
- Customization is what makes a wordmark a *mark*: a standard font with the company name typed in it is a placeholder. Adjust at least: overall tracking, one letterform detail, and the punctuation/symbol treatment.
- Pair the display face with a *different* text face for the system (unless the identity is one-superfamily, which is also valid and very Swiss).

## 5. The system around the mark

A logo is 5% of a brand. The other 95%:

- **Type system:** display + text faces, with the scale (see `typography.md`).
- **Color system:** anchor + neutrals + accent with roles (see `color-and-palettes.md` and `../assets/palettes.md`).
- **Graphic devices:** one or two recurring elements — a grid, a pattern, a shape motif, a photo treatment, a texture. Consistency here is what makes everything *look like the same brand* at a glance.
- **Voice & imagery rules:** what photography/illustration is on-brand (see `representation.md`); what the brand's tone of voice is.
- **Application:** business card, web header, app icon, social avatar, packaging, signage — the mark will be tested there, so mock those up early.

## 6. Test battery (run before presenting a mark)

- [ ] 16px favicon test — silhouette still reads
- [ ] 100m test — name/major form reads at distance (signage logic)
- [ ] One-color test — works in pure black and pure white
- [ ] Photocopy/blur test — survives a bad reproduction
- [ ] Reversed test — works on dark ground and on a photo (scrim planned)
- [ ] Construction test — all dimensions are multiples of the stated unit
- [ ] Description test — describable in one sentence
- [ ] Customization test — it is not just a stock font with the name typed in

## 7. Quick process

1. Brief: what must the brand *mean*? (one word: e.g. "precision", "warmth", "disruption")
2. Concept: 3–5 one-sentence ideas that could carry that meaning.
3. Sketch structures geometrically (construction grid) before choosing a look.
4. Reduce to 2 candidates; build both into a mini-system (type + color + device).
5. Run the test battery; fix structure, not styling.
6. Deliver: lockups (3), color variants (4), clear space, min size, one application mockup.
