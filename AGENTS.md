# AGENTS.md

Agent-orchestrated autonomous YouTube video production pipeline. The orchestrator skill is the source of truth: **read `skills/full-video-pipeline/SKILL.md` first** before any video task. The root README covers repo structure, CLI subcommands, and config keys (refreshed 2026-08); per-phase rules live in `skills/full-video-pipeline/references/phase-N-*.md` — read only the current phase's file.

## Protocol (non-negotiable)

- Drive everything through `python3 pipeline.py run|continue|complete <title>`. `complete` validates your creative artifacts AND auto-runs the following automated steps (5-6, 9-10, 13) — it is the fast path; `continue` is the manual/debug path.
- Never manually run `scripts/{render_scene,assemble,render_thumbnail,generate_voiceover,generate_voiceover_pocket,measure_durations,generate_transcript}.py` — the orchestrator adds idempotency, atomicity, and logging you would bypass.
- Never edit step-tracking fields in `videos/<title>/pipeline_state.json` (`current_step`, `attempts`, `last_error`, ...). Sole exception: set `"animations_preview_requested": true` to preview animation templates before `complete` on Step 8, or `"sfx_preview_requested": true` to export the SFX audition (mp3 + waveform PNG) at Step 10. The same applies to the render-tracking fields per scene in `scenes.json` (`render_status`, `render_hash`, `render_attempts`, `last_render_error`) — all orchestrator-owned.
- Scene re-renders are automatic: Step 9 stores a `render_hash` over each scene's TSX + shared remotion sources, so editing `SceneXX.tsx` (or `lib/styles.ts`, shared components) makes the next Step 9 re-render exactly the affected scenes. Never reset `render_status` by hand to force a re-render.
- `complete --step N --force` skips contracts — always run `python3 pipeline.py audit <title>` right after.
- The `__PIPELINE_NEXT__` JSON trailer on every command output tells you exactly what to do next (`next_cmd`, `skills_files`, `expected_artifacts`) — parse it instead of prose.

## Environment

- **Cross-platform — Windows and Linux (macOS not supported — no darwin compositor shipped).** No OS guard; render guardrails use `psutil` (portable) and Remotion picks the right native GL backend (`swangle` on Linux, `angle` on Windows). Works natively on this Windows dev box too — WSL still works but is no longer required.
- Setup: `pip install -r scripts/requirements.txt` (edge-tts, jsonschema, psutil, referencing), Node 18+, ffmpeg/ffprobe, `python scripts/check_system.py` pre-flight (`bash scripts/check_system.sh` still works as a shim). `requirements-pocket.txt` is only for the optional `pocket` TTS engine. `requirements-transcript.txt` (vosk + ~50 MB model under gitignored `models/`) is only needed for pocket-engine word timings — the default edge engine captures timings during synthesis with no extra deps. On Windows, enable long paths once (admin PowerShell: `LongPathsEnabled=1` + `git config --system core.longpaths true`) to avoid deep `node_modules` issues.
- Tests: `python -m pytest tests` — unit suite for the shared lib + orchestrator state machine. Run it after touching `pipeline.py` or `scripts/_pipeline_lib.py`.
- `skills/remotion-best-practices` is a **git submodule** the phase briefs load Remotion rules from — clone with `--recurse-submodules` or phase 3 loses its instructions. Composition guidance (phases 1/2/4) comes from `skills/video-composer` (in-repo, not a submodule). `skills/claude-youtube` remains on disk as an unwired legacy submodule.

## Structure quirks

- `videos/` is gitignored scratch (one dir per title). Per-video `videos/<title>/pipeline_config.json` is auto-discovered and overrides the repo-root `pipeline_config.json`, which `--config <path>` can also override (three-layer merge — honored by the orchestrator and every step script). `steps.{key}.command_template` values are shell-quoted automatically at substitution: never pre-quote `{token}`s in templates.
- **Audio contract**: scenes render *silent* video; the voiceover is muxed at stitch time by `assemble.py`, which pads each scene's MP3 to exactly its rendered frame count — the audio timeline equals the video timeline, so never assume raw TTS durations at cue time (author `beats` as seconds: `frame / fps`). Never put the voiceover `<Audio>` in a `SceneXX.tsx` — the `remotion-best-practices` submodule's voiceover guidance is superseded by this rule. SFX/BGM cues live in scenes.json and are mixed at stitch time by assemble.py (Step 10); a scene with no `bgm` key inherits the global default bed, `"bgm": null` opts out. Never use the remotion submodule's meme-SFX list.
- npm workspaces: `remotion-foundation` + `sfx-render` + `videos/*/remotion` (Remotion pinned to 4.0.484). Completed videos usually have `remotion/node_modules/` deleted by retention cleanup — run `npm install` there before re-rendering. Lint gate before render: `npm run lint` (and `tsc --noEmit`) inside the remotion project. `sfx-render/` is the Tone.js/WebAudio offline engine (`node sfx-render/render.js --manifest <jobs> --out <dir>`): node-web-audio-api + standardized-audio-context + tone@14; tone's ESM build is patched at runtime via `lib/tone-esm-loader.mjs` + `lib/sac-shim.mjs` (never touch).
- `animations/` is a JSON-data-driven template catalog: customize via `config/` + each template's `animation.md`, **never edit `component.tsx`**. Per-video copies under `remotion/src/components/animations/` are re-published from `animations/` on every scaffold — per-video `.tsx` edits are silently overwritten. Configs are validated against `schemas/animations.schema.json` + the template's own `config/schema.json`.
- `sfx/` is the sound catalog: bundled CC0 samples (`backend: "sample"`) or Tone.js/WebAudio recipes (`backend: "tone"` — implementation is `sfx/sounds/<id>/recipe.mjs`). Tone recipes are **deterministic**: they must source randomness from the injected `rng` (never `Math.random` — it is patched per job, but recipes must not rely on it), and dense/stochastic sounds must bake samples via the seeded helpers in `sfx-render/lib/rng.js` (never `Tone.Noise` — its process-level buffer cache leaks RNG state between jobs; never `setValueCurveAtTime` with long curves — tone expands each point into a ramp event). Recipes re-render when their `.mjs` sha256 changes (folded into `sfx_hash`). After editing any recipe, regenerate `sfx/preview/catalog-preview.html` via `python scripts/export_sfx_preview.py --catalog`. Cue moods are machine-checked vs `style.mood` (warning-level). Never edit generated `videos/<title>/sfx_aligned.mp3` / `bgm_aligned.mp3` by hand — they're rebuilt from cues.
